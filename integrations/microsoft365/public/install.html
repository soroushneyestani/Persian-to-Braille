What is available in this preview

Braille Hub uses the same public SDK and Core across supported Office hosts. The Office layer handles selection, files, preview, and document insertion; Braille rules remain in the shared engines.

Persian → Braille

Forward Persian Braille translation through the shared Core and SDK.

English / Latin → Braille

Ordinary uncontracted six-dot English/Latin through the current Latin-span rules. This is not a claim of contracted UEB / English Grade-2 support.

German → Braille

Deutschland / Österreich and Schweiz with Basisschrift, Vollschrift, and Kurzschrift.

Persian Braille → Persian

Stateful reverse translation with explicit ambiguity handling.

MIDI → Braille Music

Standard MIDI files are processed through the semantic music path and shared Braille Music engine.

MusicXML / MXL → Braille Music

`.musicxml`, `.xml`, and compressed `.mxl` sources use the dedicated MusicXML compatibility pipeline and the same Braille Music engine.

Microsoft 365 hosts

Word

Text translation plus the current MIDI and MusicXML file workflows. Successful previews can use Word-safe write operations.

Excel

Translate one selected plain-text cell and replace it after preview.

PowerPoint

Translate a selected text range and replace it after preview.

Shared architecture

Microsoft365 → SDK → Core / Music. No separate browser or Mac Braille engine.

Current verified scope: Windows Desktop is live verified. Office on the Web has been validated. macOS manifest sideload has been user-reported working; the direct `.pkg` installer remains a release candidate pending final tester confirmation.

Windows Desktop Preview

For Microsoft 365 Desktop on Windows, the preview installer prepares the same local network-share catalog and trusted Office add-in catalog used by the verified Windows sideload flow.

Download Windows Desktop Preview Installer

  1. Download and run the Windows Desktop Preview Installer.
  2. Allow the Windows UAC prompt if it appears.
  3. Close and reopen Word, Excel, or PowerPoint after setup.
  4. Select Home → Add-ins.
  5. Choose Get Add-ins, or Advanced when that label is shown.
  6. Open the SHARED FOLDER tab.
  7. Select Braille Hub.
  8. Choose Add.
  9. Use Translate Selection from the ribbon.
The installer downloads the production manifest over HTTPS, creates a local add-in catalog, and registers it for the current Windows user. It does not install a second Braille engine inside Office.

  1. اگر Word، Excel یا PowerPoint باز است، آن‌ها را ببندید.

Braille Music from MIDI — Word Desktop / Windows

Braille Music has been live verified in Microsoft Word Desktop on Windows. Standard MIDI files with a .mid or .midi extension are read locally by the add-in.

  1. Open Braille Hub in Microsoft Word Desktop.
  2. Select the Music / MIDI tab.
  3. Choose a Standard MIDI file.
  4. Choose exactly one MIDI line. A line is one Track + Channel pair.
  5. Select Preview Music Braille to generate Unicode Music Braille and BRF / Braille ASCII.
  6. Select Insert Music Braille to insert the exact successful preview at the current Word caret or selection.

No notes inside the selected line are automatically removed based on instrument, percussion, program, or channel classification.

Some complex MIDI lines may not yet be representable by the current notation bridge. Those lines fail explicitly instead of silently deleting or simplifying musical material. Choose another source line when appropriate.

Whole-song multi-line / All Lines conversion is not exposed in this preview.

MusicXML / MXL — Word Desktop / Windows

  1. Select the separate MusicXML tab.
  2. Choose `.musicxml`, `.xml`, or `.mxl`.
  3. Preview the Braille Music result.
  4. Insert the successful preview into Word.
This is a Windows sideload/testing convenience and is not Microsoft Marketplace publication. Microsoft documents network-share deployment as a testing mechanism and states that it is not supported for production add-ins. It is used here only for preview/testing, not as the final Marketplace distribution method.

Mac preview

The direct macOS package installs the same production Braille Hub manifest into the supported Microsoft Office sideload directories. It does not contain a separate native Braille translation engine.

Download Braille Hub Mac Preview Installer (.pkg)

  1. Close Microsoft Word, Excel, and PowerPoint.
  2. Download Braille-Hub-Mac-Preview-Installer.pkg.
  3. Open the package and complete the macOS Installer steps.
  4. Reopen Word, Excel, or PowerPoint.
  5. Open Home → Add-ins and select Braille Hub.

Office sideload targets

~/Library/Containers/com.microsoft.Word/Data/Documents/wef ~/Library/Containers/com.microsoft.Excel/Data/Documents/wef ~/Library/Containers/com.microsoft.Powerpoint/Data/Documents/wef
Release-candidate note: The first macOS `.pkg` may be unsigned until Apple Developer ID Installer signing and notarization are configured. Do not disable macOS security features. If macOS blocks a trusted test package, use the normal Privacy & Security flow provided by macOS.

راهنمای نسخه macOS

Individual preview — Office on the web

Office on the Web uses the same hosted Office.js task pane, public SDK, Core, and Music package boundaries as the desktop add-in.

  1. Download the manifest from this page.
  2. Open Word, Excel, or PowerPoint in Office on the web.
  3. Open a document or presentation.
  4. Select Home → Add-ins → More Settings.
  5. Select Upload My Add-in.
  6. Choose the downloaded manifest XML file and upload it.
Office on the Web was closed as a validation phase: no separate Web Braille engine or Web-only language implementation was required.

Organization deployment — Microsoft 365 admin

  1. Open the Microsoft 365 admin center.
  2. Go to Settings → Integrated apps.
  3. Open the Add-ins deployment flow.
  4. Choose the custom add-in option.
  5. Upload the downloaded manifest, or provide the stable manifest URL when the tenant UI offers URL-based manifest upload.
  6. Assign the add-in to the intended users or groups.
The production manifest is also the common source used by the Windows and macOS preview distribution paths. Development `localhost` URLs are not used by the hosted manifest.
